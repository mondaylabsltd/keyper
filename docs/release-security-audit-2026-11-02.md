# Keyper 发布前安全审计（2026-11-02）

## 结论

**不能将当前产品描述为“没有安全隐患”。** 本次发现并修复了自动填充隔离、离线检查、遮挡触摸和派生任务生命周期的问题；但人类自选文本的离线猜测风险仍然存在。安全评分可能把公开文本评为“强”，不能据此判断其适合保护资产。iOS 截屏保护还依赖系统未承诺的内部视图行为；后续已在 iPhone 15 Pro / iOS 26.5.2 完成系统截图与 USB 捕获验证，当前设备通过，仍不能推广到全部系统版本。详见[真机验证记录](ios-device-screen-audit-2026-11-02.md)。

发布建议：完成本文的发布前剩余项，再决定是否发布。对于用户自行编写记忆文本的模式，不建议以“强评分”“破解要数亿美元”作为资金安全依据。本次是源码、构建产物与本地测试审计，不是独立第三方渗透测试或密码学证明。

### H-01：强度模型不能测量自选文本的真实熵

`Strength.of()` 根据字符类型、顺序和重复分配分数，不识别公开句子、歌词、口令复用或个人信息。直接调用当前 Kotlin 实现，对公开的美国效忠宣誓开头句（从 “I pledge allegiance” 到 “United States of America”）得到：

```text
STRONG
79.94294349584874 bits
model cost USD 3.2279101178423738E17
```

这不是该句的真实熵或实际破解价格。它是可直接收入猜测字典的公开文本。此证据说明评分可能严重失真；本次没有据此测量攻击者的实际 GPU 吞吐量或电费。

邮箱与公开域常量均不提供秘密熵；Argon2id 只能增加每次猜测的成本，不能把低熵输入变成高熵秘密。12 或 24 个输出词的长度，也不能增加输入本身的不可猜测性。关于人类自选密码的猜测风险，可参见[原始研究](https://www.usenix.org/conference/usenixsecurity16/technical-sessions/presentation/melicher)；历史 brainwallet 研究采用的算法不同，其具体破解成本不能直接套用到 Keyper。[研究原文](https://discovery.ucl.ac.uk/id/eprint/10154816/)

本次缓解：两个平台始终显示评分的识别盲区，即使评级为“强”；成本旁标明只是模型估算。商店中英文文案删除“攻击者每次也必须花一分钟”等不成立的承诺。不修改冻结协议或评分对应的派生结果。

**剩余决策：** 若产品希望给出可核验的高熵保证，需要另行设计使用系统安全随机源生成输入/助记词的模式；新模式必须与现有 v1 恢复路径明确区分，不能悄悄改变已有用户的派生结果。仅增加常见名句黑名单也不能解决此问题。

### H-02：Android 自动填充边界

原根布局只有 `importantForAutofill="noExcludeDescendants"`。这是自动填充参与提示，不是绝对的数据隔离；显式请求可带 `AUTOFILL_FLAG_INCLUDE_NOT_IMPORTANT_VIEWS`。[Android 官方 API](https://developer.android.com/reference/android/view/View#AUTOFILL_FLAG_INCLUDE_NOT_IMPORTANT_VIEWS)

修复前的设备测试确认：

1. 按框架的显式请求标记调用真实视图树的数据提供方法，可取得敏感输入。
2. 调用字段的自动填充入口后，字段内容变成测试字符串 `injected`，绕过内置键盘。

测试通过 `RecordingStructure` 记录框架接收到的文本及 AutofillValue，并用同一安全窗口中的普通 EditText 作正对照。该测试验证数据边界，不等同于完整的恶意 AutofillService 远程利用链：外部利用还取决于系统/服务能否触发显式请求或已有填充会话，本次未建立完整服务 PoC。

修复：新建 `PrivateLayout`，禁止主页面及恢复演练子树导出自动填充结构；`KeyperField` 不声明填充类型，不提供敏感填充结构，拒绝填充响应。测试同时检查邮箱、口令、逐个助记词单元和四个输入框的注入入口。

### M-01：iOS 离线检查的操作时机

修复前新增回归在以下场景失败：在线直接调用 `generateAnyway()` 仍启动派生；两次轮询之间网络变更后，生成、复制及“改用二维码”仍执行。影响主要是绕过应用承诺的离线边界；没有发现 App 自身上传数据的网络实现。

修复：在生成、派生开始、复制、二维码和恢复演练入口重新调用监测器；派生入口统一检查离线、忙碌和演练状态。接口枚举失败时按未知连接处理并保持锁定。原有输入仍不能在已知在线状态下输入或生成。

### M-02：Android 遮挡触摸

旧实现保护截图，但没有独立阻止其他窗口覆盖时的点击。Android 12 起有部分系统拦截，但部分遮挡并无默认保护。[Android 官方风险说明](https://developer.android.com/privacy-and-security/risks/tapjacking)

修复：主窗口及每个安全弹窗的 `Window.Callback` 同时过滤全遮挡与部分遮挡标记；遮挡在一次手势中途出现时发送 CANCEL，防止之后的 UP 提交先前按键。没有增加权限。

回归通过构造带系统遮挡标记的触摸事件验证主窗口和确认弹窗，并验证无遮挡点击仍有效。本次未额外安装一个恶意覆盖层 App；系统是否正确产生遮挡标记仍属于平台边界。

### M-03：Android 派生完成顺序

旧任务的完成回调先执行 `setBusy(false)`，之后才检查任务 ID。如果取消后已开始新任务，旧回调会提前开启输入和生成按钮。修改输入后仍可能接收新任务基于旧输入生成的结果。

修复：取消时释放忙碌状态；过期结果先校验 ID 并擦除，不能修改新任务界面；生成入口检查忙碌状态。新派生开始前丢弃并擦除旧结果。回归模拟“取消后重启，旧结果晚到”，确认输入持续禁用且不能再启动并发任务。

### M-04：iOS 屏幕保护

`ScreenShield.make()` 从安全文本框取内部容器作为页面载体。如果取不到，旧实现返回普通 UIView，应用继续工作而失去这层截屏保护。本次改为清空输入和结果、不挂载敏感页面，仅展示“屏幕保护不可用”的提示，并增加缺失容器回归测试。模拟器及后续真机测试验证了所测系统版本的容器和屏幕遮挡行为，但不能证明其他设备及未来系统均安全。

Apple 仅描述 `isSecureTextEntry` 对文字在某些情况下的录制/广播保护，没有承诺应用任意子树可永久借用此内部容器。[Apple API](https://developer.apple.com/documentation/uikit/uitextinputtraits/issecuretextentry)

后续已在 iPhone 15 Pro / iOS 26.5.2 上验证实际系统截图、USB 视频捕获和前后台往返，Release 系统截图也通过；控制中心原生录屏成片、AirPlay 和实际多任务卡片像素比对仍未覆盖。应继续验证其他支持设备，并考虑使用公开的捕获状态 API 隐藏敏感页面。缺失容器的回退路径已阻止敏感操作，但无法凭“容器存在”证明所有系统版本的捕获行为。捕获状态不能阻止已发生的单次截图。[Apple 官方指导](https://developer.apple.com/documentation/swiftui/protecting-sensitive-content-when-screen-sharing)

两个平台页脚现在显示 `Keyper v1 · <12 位 Git commit>`，有未提交修改则附加 `-dirty`。Android 使用 Gradle Provider 将 Git 状态纳入配置缓存输入；iOS 每次构建生成包内 `BuildRevision.txt`。

## 已确认的保护与边界

- Android Release 合并清单没有 uses-permission；没有 INTERNET/共享存储权限；`allowBackup=false`；没有 debuggable=true；对外仅有启动 Activity，剪贴板 JobService 不导出且要求系统绑定权限。
- Android Release 运行依赖树仅含 Kotlin 标准库、annotations 和项目 core；对已跟踪文件的常见私钥/令牌格式检查未命中，历史文件名检查也未发现 keystore/PEM/环境密钥文件。这不是全格式密钥扫描或供应链恶意代码证明。
- 发布 APK 经 apksigner 验证通过，使用 MONDAY LABS LTD 证书，而非 Android Debug 证书。当前本地证书 SHA-256：`68f059718a270173ac60420183dbfd25e1ca72e8afa2c8ffcfa0e04103773c8d`。Google Play 分发证书可能因 Play App Signing 与本地上传证书不同，发布后须以控制台证书为准。
- 生产代码审阅未发现网络请求、远程 WebView、遥测 SDK 或将输入/助记词写入文件、数据库、日志的路径。iOS 仅保存语言偏好；包内版本资源不是用户数据存储。
- Kotlin 和 Swift core 的协议向量及参考夹具通过；覆盖 Argon2id RFC 向量、48 组参数夹具、BIP39、词表摘要、QR、邮箱规范化和恢复指纹。向量一致不等于对手写密码实现的独立形式化审计。
- Argon2 工作内存完成和取消后均有擦除测试；取消会等待计算线程退出。String、GC、Swift 写时复制及库内部状态无法保证全部可验证擦除，不能承诺内存取证安全。
- Android 10+ 剪贴板后台读取受限，清理可能要等应用回到前台；系统冻结、杀进程和其他应用的历史副本也会影响清理。iOS 使用本机限定和过期时间，但不能删除其他应用已保存的副本。这是平台残余风险，商店文案已明确说明。
- Android 旧系统、获授权的辅助功能工具、root/jailbreak、恶意系统、物理摄像头不在这些保护的可靠防御范围。离线门禁是状态检查，不是操作系统级网络隔离证明，特别要实测 USB/以太网、VPN 和厂商无线状态。
